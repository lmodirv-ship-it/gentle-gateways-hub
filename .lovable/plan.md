
# لوحة "إيراداتي ومصاريفي" — Unified Revenue Dashboard

لوحة شخصية محمية بتسجيل دخول، تجمع في مكان واحد:

1. **مصاريفك على Lovable** (يدوي + رابط للفوترة الرسمية).
2. **إيرادات مواقعك الـ124** المسحوبة من مزوّدي الدفع عبر API.
3. **قائمة المواقع** وحالة ربط الدفع لكل موقع.

---

## حقيقة مهمة قبل البدء

- **Lovable لا تستلم أموال زبائنك.** المدفوعات تذهب مباشرة من الزبون إلى مزوّد الدفع المربوط بالموقع (Stripe / Paddle / Shopify / PayPal …). إذن "إيرادات مواقعك" تُجلب من مزوّدي الدفع، لا من Lovable.
- **Lovable لا توفّر API عاماً** لقراءة كم تدفع أنت لها من داخل تطبيق. سنعرض رقم المصاريف يدوياً (أنت تُحدِّثه شهرياً) مع رابط مباشر لـ `Workspace Settings → Plans & Credits` للتحقق.
- **هذا المشروع معزول** عن مشاريعك الأخرى الـ124؛ لا يستطيع قراءة بياناتها مباشرة. لذلك سنُدخل كل موقع + مفتاح مزوّد الدفع الخاص به مرة واحدة، ثم تعمل اللوحة تلقائياً.

---

## ما سيُبنى — على مراحل

### المرحلة 1 — البنية والحماية
- تفعيل Lovable Cloud (DB + Auth + Secrets).
- تسجيل دخول: بريد + Google.
- جميع الصفحات تحت `_authenticated/` ولا تُفتح إلا لك.

### المرحلة 2 — قاعدة البيانات (مع RLS صارمة)
- `sites` — اسم الموقع، الدومين، الفئة، العملة، الحالة.
- `payment_connections` — لكل موقع: نوع المزوّد (stripe/paddle/shopify/paypal/gumroad/lemonsqueezy/manual)، مرجع إلى Secret يحوي المفتاح، الحالة (متصل / يحتاج مفتاح / خطأ).
- `revenue_snapshots` — كاش يومي (site_id، date، gross، net، refunds، currency) لتسريع العرض وتقليل استدعاءات API.
- `lovable_spend` — إدخال شهري لمصاريفك على Lovable.
- `fx_rates` — أسعار صرف يومية لتوحيد العملات.
- `user_roles` + `has_role()` — نمط الأدوار الآمن.

### المرحلة 3 — استيراد الـ124 موقعاً دفعة واحدة
- بذرة (seed) أولية تُدخل القائمة الكاملة التي أرسلتها (16 موقعاً على نطاق `.lovable.app` + باقي الدومينات المخصّصة) في جدول `sites` بحالة "بانتظار ربط الدفع".
- صفحة `/import` لإدارة الاستيراد لاحقاً عبر CSV.

### المرحلة 4 — موصلات مزوّدي الدفع (Server Functions فقط)
دوال خادم تستخدم المفاتيح من Secrets (لا تصل أبداً للمتصفّح):
- `fetchStripeRevenue(siteId, range)` — Stripe Balance Transactions.
- `fetchPaddleRevenue(siteId, range)` — Paddle Transactions.
- `fetchShopifyRevenue(siteId, range)` — Shopify Orders.
- `fetchPayPalRevenue(siteId, range)` — PayPal Transactions.
- `fetchGumroadRevenue` / `fetchLemonSqueezyRevenue`.
- موصل **Manual** للمواقع بلا API (تُدخل المبلغ شهرياً).
- مهمة مجدولة `/api/public/cron/sync` (محمية بـ HMAC) تحدّث `revenue_snapshots` يومياً.

### المرحلة 5 — صفحات الواجهة
- `/` لوحة رئيسية:
  - بطاقات: إيراد اليوم / الشهر / السنة (مجموع كل المواقع).
  - "صافي بعد Lovable" = الإيراد − مصاريف Lovable.
  - رسم بياني زمني قابل للتبديل (يومي/شهري/سنوي) — Recharts.
  - أعلى 10 مواقع من حيث الإيراد.
- `/sites` جدول الـ124 موقعاً: اسم، دومين، مزوّد، حالة الربط (✅/⚠️)، إيراد الشهر.
- `/sites/:id` تفاصيل موقع + آخر معاملات + زر "تحديث الآن".
- `/sites/:id/connect` لصق مفتاح API بشكل آمن (يُخزَّن كـ Secret).
- `/lovable-spend` إدخال المصاريف الشهرية + رابط صفحة الفوترة.
- `/import` استيراد CSV لاحقاً.

### المرحلة 6 — الأمان والجودة
- كل المفاتيح في Secrets، لا في الكود.
- `requireSupabaseAuth` على كل Server Function؛ تحقّق من ملكية الصف.
- في حال فشل API لمزوّد، تُعرض آخر لقطة من الكاش مع تنبيه.
- اختبار سريع لكل موصل.

---

## ما ستحتاج تزويدنا به لاحقاً (بعد تشغيل اللوحة)

- لكل موقع يبيع فعلياً: مفتاح API الخاص بمزوّد الدفع (Stripe Secret Key، Paddle API Key، Shopify Admin Token، PayPal Client ID/Secret …).
- المبلغ الشهري الذي تدفعه لـ Lovable (مرة كل شهر).

لن أتوقّف لانتظار هذه المفاتيح؛ سأبني البنية والواجهة كاملة، وستظهر الـ124 موقعاً مباشرة مع شارة "يحتاج ربط دفع"، ثم تضيف المفاتيح عند الحاجة.

## التقنيات
TanStack Start + Lovable Cloud (Supabase) + TanStack Query + Recharts + Tailwind + RLS صارمة + `pg_cron` للمزامنة اليومية.

عند موافقتك، أبدأ مباشرةً بالمرحلة 1 وأكمل المراحل تباعاً دون توقف.
